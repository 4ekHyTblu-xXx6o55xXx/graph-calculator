## 3. Границы системы

### Что система делает
- Принимает математические выражения функций одной переменной $y = f(x)$ и двух переменных $z = f(x, y)$.
- Проверяет корректность синтаксиса и баланс скобок.
- Поддерживает стандартные операции (`+`, `-`, `*`, `/`, `^`, `%`), константы (`pi`, `e`), функции одного аргумента (`sin`, `cos`, `tan`, `cot`, `sqrt`, `cbrt`, `ln`, `exp`, `abs`, `floor`, `ceil`) и двух аргументов (`min`, `max`, `pow`, `hypot`, `atan2`).
- Вычисляет значения выражений с плавающей точкой (IEEE 754 double).
- Табулирует функцию $f(x)$ на отрезке $[x_{min}, x_{max}]$ с шагом $dx$.
- Строит двумерную сетку значений `Grid2D` для функции $z = f(x, y)$ на области $[x_{min}, x_{max}] \times [y_{min}, y_{max}]$.
- Отслеживает точки разрыва (деление на ноль, отрицательные аргументы под корнем) без падения программы.
- Выводит график функции одной переменной в консоли (символьный холст с осями).
- Выводит функцию двух переменных в виде консольной карты уровней (символьной матрицы высот).

### Чего система НЕ делает
1. Не производит символьное (аналитическое) дифференцирование и интегрирование (не является CAS-системой).
2. Не находит аналитические корни уравнений в общем виде.
3. Не поддерживает вычисления с комплексными числами (только вещественные числа $\mathbb{R}$).
4. Не поддерживает пользовательские скрипты, циклы и создание собственных макросов/функций.
5. Не строит полигональные 3D-модели с аппаратным 3D-ускорением (OpenGL/DirectX); функция $z=f(x, y)$ проецируется на плоскость.
6. Не хранит данные на удаленных серверах и не требует подключения к сети.
7. Не поддерживает работу с числами бесконечной точности (ограничено точностью типа float).

### Предположения
- Входные данные подаются в кодировке UTF-8 или ASCII.
- Пользователь вводит формулы в стандартной математической нотации.
- Для выполнения проекта требуется Python 3.10+ или среда Docker на базе Ubuntu 24.04.

### Открытые вопросы
1. Как визуализировать точки неустранимых разрывов (например, $\tan(x)$ или $1/x$): прерывать отрезок графика или отображать пунктирную асимптоту?
2. Какой способ отображения функции двух переменных $z = f(x, y)$ на плоскости будет выбран основным для графического интерфейса: цветовая карта (heatmap), контурные линии уровней или каркасная проекция (wireframe)?
3. Какова стратегия при переполнении (`OverflowError`): возвращать бесконечность ($\infty$) с отсечением по границам холста или прерывать табуляцию с предупреждением?
4. Как организовать расширение набора функций в последующих вехах без изменения кода парсера?
